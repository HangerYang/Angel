Where the compressor looks

Each image tile is 64 visual tokens laid out on an 8×8 grid. The compressor is supposed to blend them into one summary. It doesn't blend — it picks one and discards the other 63. These maps show which of the 64 it picks.

Where the pick lands on the tile

Each square is one of the tile's 64 token slots, in reading order. The number is the percentage of all 626 tiles whose pick landed there. Uniform would be 1.6% everywhere. Each map is scaled to its own maximum, printed below it.

The target's own map is nearly flat (1.3%–2.9% against 1.6% uniform), with a slight lift on the border and a peak at slot 63 — the tile's last token, which behaves like an attention sink. Run 2 lands on that same slot 84.8% of the time.

What the maps say

  • 0.6%

    Run 1 agrees with the target less often than random. It hits the target's most-attended slot 0.6% of the time against 1.6% for chance. Instead it has a positional habit: about 40% of its picks land in the tile's top row, concentrated on three slots.

  • 84.8%

    Run 2 collapsed onto one corner. Adding the target-attention pre-filter made it worse, not better: five sixths of all picks are slot 63, the tile's last token. It stopped looking at the image and learned a constant.

  • 1.86×

    The target barely discriminates either. Its own attention peaks at 1.86× uniform on slot 63 and is otherwise flat, so a top-16 pre-filter selects a border-biased set rather than a semantically salient one.

Why training produced this

The compressor is trained by the drafter's next-token loss alone — there is no reconstruction or fidelity term anywhere. Three facts stack up:

  1. The drafter barely uses visual tokens. Training top-1 accuracy with all 832 visual tokens is 0.6892; with 13 it is 0.6895. Identical. So the gradient reaching the routing weights carries almost no information about which region matters.
  2. Nothing regularizes the routing. weight_decay = 0.0 and no entropy penalty, so ‖k_proj‖ grows without bound — the raw logit range reached 173,616 against a temperature of 8. Sharpening always shaves a little loss, and nothing pushes back.
  3. With no value projection, a one-hot weight vector makes the "summary" a verbatim copy of one token. The convex combination degenerates to a corner of the simplex.

So this is not a compressor that learned the wrong thing. It is a compressor whose objective never constrained it, drifting to a fixed positional habit while the loss looked fine.
